# Chromatic boundaries — bounded experiment

**2026-09-27 · experimental, not an enforcement mechanism.**

Перевіряємо, чи колірна карта допомагає знайти змішані відповідальності та чи типізовані
«порти» відрізняють повідомлення від повноваження. Production Rust-код не змінено.
Python 3, стандартна бібліотека; Linux, root і доступ до мережі не потрібні.

## Відтворення

Із кореня репозиторію:

```sh
python3 experiments/chromatic-boundaries/check.py
python3 -m unittest discover -s experiments/chromatic-boundaries -v
```

Перша команда оновлює [result.json](results/result.json) і [колірну карту](results/map.html).
Друга запускає позитивні та негативні контроли. Для окремого manifest:

```sh
python3 experiments/chromatic-boundaries/check.py --manifest path/to/manifest.json --ports-only
```

Port verdict повертає exit 1 при порушенні й 0 при прийнятті. Загальний inventory повертає
0 навіть за знайдених циклів чи непідтверджених гіпотез: це звіт, а не gate для production.
Невалідні структури manifest можуть завершитися Python-помилкою; це прототип, не стабільний CLI.

## Що реалізовано

- 14 реальних файлів, SHA-256 кожного, Git SHA, hash manifest та checker у результаті.
- Обмежене лексичне виділення `crate::name`, оголошень `mod` та `common::audit_log`.
  Ручна таблиця aliases пов'язує `SentinelDb` з коренем `main`, а `MeshCommand` з `mesh_sync`.
- Сигнали можливих ефектів із рядками: filesystem, host discovery, sockets, Aya, clock,
  subprocess, logging, unsafe, signing. Імпорт типу теж може бути сигналом, не викликом.
- Транзитивна досяжність, шляхи до сигналів, компоненти взаємної досяжності.
- Незалежна перевірка **запропонованих** портів: напрям, schema, наявність потрібних
  capabilities та дозволений набір ефектів. Усі ці властивості задані manifest, не витягнуті
  з runtime. Поле `grants` — тестова декларація, не справжній credential.
- Негативні контроли, включно зі зміною source-файла у тимчасовому каталозі без зміни manifest.

## RGB, Alpha та scale

Для цього досліду RGB — груба, свідомо змінювана проєкція **сигналів ефектів**, не вимір
повноважень і не топологічний ранг:

| Канал | Сімейство сигналів |
|---|---|
| R | host_read, disk, kernel, process, unsafe |
| G | network, ipc |
| B | clock, log, sign |

Кожен канал поки має лише два значення: `0` або `F`; це 8 кольорів у форматі `#RGB`.
Чорний означає «сигналів не знайдено в обраному охопленні», **не** доведену чистоту чи нульові
повноваження. Сімейства не задають порядку небезпеки: диск і ядро мають той самий колір,
але різні capability contracts. Колір не визначає допуск до порту.

Alpha показана текстом: `F` — є прямий лексичний сигнал; `?` — невідомо. `0 = proven pure`
прототип не присвоює. Наявність `unsafe` сама по собі не доводить side effect, а локальна
мутація не фарбується автоматично. Для уникнення хибної гарантії це **не готовий RGBA-тип**.

Два масштаби вже доступні: direct signals файла та union сигналів його reachable dependencies.
Union ніколи не приховує сигнал усередненням. Це масштаб агрегації, не fixed-point точність.
`q=0` у manifest — зарезервована метаінформація; Q-арифметика не реалізована, зміна q нічого
не змінює. Для нечислових capabilities потрібні множини/підмножини, не дробові рівні доступу.

## Порти

Позитивні пари: detector→policy (`observation/v1`), operator→enforcement (`decision/v1`),
enforcement→exporter (`outcome/v1`), operator→trust (`trust-update/v1`).

Негативні пари доводять, що правильного schema та навіть дозволених ефектів недостатньо:
peer із `trust-update/v1` і бюджетом disk однаково не має `change_trust`.
Це логічні API-порти; номери TCP/UDP не змінюються, мережеві слухачі не запускаються.

## Межі гарантій

Це не Rust parser, type checker, call graph, security audit чи доказ чистоти. Макроси,
trait dispatch, callbacks, handles, FFI, external crates, aliases поза ручною таблицею,
`super::` та всі варіанти `use` не розв'язуються повністю. Документований негативний приклад:
`some_external_crate::hidden_io()` не дає сигналу. Тест зберігає цю межу видимою.

Коментарі, звичайні/raw рядки та символьні літерали маскуються; відкидається хвіст від
точного `#[cfg(test)] mod tests {`. Решта cfg не обчислюється. Не всі Rust-файли й сторонні
залежності включено. `unresolved` показує лише нерозв'язані посилання підтриманого синтаксису,
а не весь пропущений код. Hash source-файла включає й частину, виключену з inventory.

Reachability до effectful модуля не доводить effectful виклик. Модульний цикл не означає
циклічних crate-залежностей Cargo, нескінченної рекурсії чи вразливості. Лексичні висновки
служать для вибору місць ручного аналізу.

Зелений port fixture доводить лише узгодженість декларацій. Компрометований автор manifest
може сам вписати `change_trust`; реальний runtime мусить отримувати capability від довіреної
межі й перевіряти його. Прототип не створює такої межі.
