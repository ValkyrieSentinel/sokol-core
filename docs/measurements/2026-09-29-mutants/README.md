# Мутанти ключових залежностей (T2, 2026-09-29)

Пункт 4 контракту відновлення з оцінки переносу 2026-09-28: зламати ключову залежність — і
відповідна перевірка має впасти. Кожен мутант — одна заміна в коді; прогнано весь набір
юніт-тестів orchestrator (`cargo test -p orchestrator --bin orchestrator`, aarch64, Docker).

| Мутант | Заміна | Хто ловить |
|---|---|---|
| M1 Без пріоритету заявок | `Claim` вилучено з `MeshCommand::urgent()`: заявки йдуть у bulk-чергу | `claims_go_first_and_reports_are_dropped_first` |
| M2 Без прибирання закінчених заявок у тіку | фільтр мертвих заявок у `tick` завжди `false` | до цього PR — лише модельний фазер (`machine::the_table_keeps_its_invariants`); тепер ще й `expired_claims_are_forgotten` |
| M3 Без повтору desired→applied | 0 повторів за тік | 5 тестів, зокрема `a_failed_removal_is_not_reported_and_is_retried`, `a_block_the_map_cannot_take_is_pending_not_counted_and_retried`, фазер |
| M4 Бюджет кадрів не поповнюється | `elapsed × rate` → 0 | `a_bucket_allows_its_burst_then_paces`, `a_fast_peer_is_paced_not_dropped` |

M2 виявився не тим, чим здавався. Він не зберігає блок: знімання йде через `until_ms`, тож
блоки знімались вчасно. Він лише не прибирав мертві заявки з пам'яті, тобто був мутантом
витоку. Прямого тесту на це не було; `expired_claims_are_forgotten` його додає і падає на
мутанті (`left == right failed: ended claims are dropped from memory`).

Раніше вбиті мутанти контрактів:
- без ремонту через дайджести → `bench/mesh.sh recover` L3 (docs/measurements/2026-09-28-lab);
- замикання, що рахує, але не чекає → `a_fast_peer_is_paced_not_dropped` (#66);
- кеш повторів без межі на відправника й без вивернення (#69);
- ABI: поміняні поля ламають збірку (#58).

## Пункт 1 T2 (перевантаження bulk) — що перевірено, а що ні

- `bench/mesh.sh recover` перевантажує **термінову** чергу, тобто заявки, і тримає команди
  оператора (L1 ≤ 1 с). Bulk (дайджести, телеметрія) у цей час витісняється суворим
  пріоритетом. Те, що вона відновлюється після навантаження, показує L3 — збіг за 62 с.
- Окремого флуду саме bulk немає. Bulk-трафік генерує сам вузол (періодична телеметрія й
  дайджести), зовнішнього джерела для нього немає, тож тест вимагав би спеціальної ручки в
  коді. Не додавав.
