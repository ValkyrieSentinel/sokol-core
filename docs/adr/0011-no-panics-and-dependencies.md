# ADR-0011. Код без паніки й політика залежностей

**Статус:** реалізовано (PR #34, #36, #40). **Дата:** 2026-09-27.

## Контекст

Release збирається з `panic = "abort"`. Будь-яка паніка на шляху даних зупиняє **весь вузол**.
Шлях даних — це кадр піра, рядок IPC, з'єднання з пасткою, файл. Залежності безпекового
продукту мають бути підтримуваними, з відомою ліцензією й відтворюваними.

## Рішення

- **Без паніки поза тестами.** У всіх корнях крейтів заборонено `clippy::{unwrap_used,
  expect_used, indexing_slicing, string_slice, panic, unreachable, todo, unimplemented}`. Крок
  Clippy у CI це забезпечує. Виняток — лише локальний `allow` з причиною.
- **Залежності.** `cargo deny check` для обох робочих просторів перевіряє:
  - вразливості й yanked-версії;
  - лише пермісивні ліцензії;
  - лише crates.io як джерело;
  - відсутність wildcard-версій.

  Кожен виняток записується в `deny.toml` з причиною; зараз винятків немає.
- **Відтворюваність.**
  - Nightly закріплено датою в `rust-toolchain.toml`.
  - Завантажені інструменти перевіряються за sha256, actions закріплені за комітом.
  - Кожен прогін CI публікує бінарники з `MANIFEST.txt` і `SHA256SUMS`.

## Наслідки

- Лінт — фільтр, а не доказ. `indexing_slicing` не ловив нарізання `str` (R27-01), тому
  додано `string_slice`. Для парсерів, куди потрапляють дані ззовні, потрібні ще й
  property-тести на довільних входах.
- Артефакт прогону CI — не реліз. Реліз — окремий запис доказів для конкретного SHA.

## Перевірка

- CI: fmt, `cargo deny check`, збірка з `--locked`, тести, Clippy з `-D warnings`, smoke і демо.
- Property-тести парсерів: валідатор JSON (диференційно зі старою реалізацією), ключі
  (`no_key_text_panics`).

## Коли переглянути

При зміні профілю збірки (наприклад, `panic = "unwind"` з ізоляцією задач) або появі
підтримуваної заміни для залежності з обмеженнями.
