# ADR-0020. Профіль FlowSpec, вибір backend і межа подальшої роботи

**Статус:** реалізований CLI-профіль; придатність deployment підтверджує його
відповідальний оператор. **Дата:** 2026-10-05. **База:** `608fcc9`.

Уточнює ADR-0008: його семантика RIB, перевірки й історія R1–R13 залишаються чинними.
Це рішення про технічний профіль і розподіл роботи, не підтвердження пілоту.

## Рішення

Залишаємо GoBGP 4.9.0 CLI для поточного профілю. Не починаємо міграцію на gRPC
чи наступне розширення reconciliation лише тому, що можна знайти ще один край.
Наступний пріоритет — qualification на цільовій NIC, визначене навантаження,
оператор і прийняті ним пороги; лабораторний CI їх не замінює ([ROADMAP](../../ROADMAP.md)).

### Передумови deployment

- Один writer володіє community Sokol; повторне використання цього тега іншими
  writers, зокрема на прихованих nonzero-ID paths, виходить за підтримуваний профіль.
- Керовані локальні source-only NLRI мають фактичний ID zero. CLI JSON не доводить
  цього: GoBGP 4.9.0 може повідомити `LocalID: 0` без фактичного identifier.
- Writers на спільному gobgpd мають окремі керовані NLRI або зовнішню серіалізацію
  read/apply операцій, що можуть конфліктувати. Вона має враховувати вже прийняті
  RPC з невідомим результатом; lock лише навколо запуску CLI недостатній.
  Різні communities самі не ізолюють записи. Така серіалізація не реалізована Sokol.
- Оператор підтверджує ці передумови до увімкнення FlowSpec та узгоджує прийняття
  правил upstream. Sokol пропускає спостережені чужі локальні колізії, але не
  перевіряє ексклюзивне володіння daemon або відсутність усіх конкурентних writers.

### Прийняті межі

Непридатний initial RIB read забороняє записи раунду. Непридатний post-write read,
timeout чи скасування не підтверджують відсутності ефекту; наступна спроба читає
RIB заново. CLI-ACK audit фіксує успішну відповідь CLI, а не спостережений discard.
Health, convergence, progress і age зберігають різні значення з ADR-0008.

Не гарантуємо CAS, rollback або fence для прийнятого RPC, безпечну роботу
неузгоджених writers зі спільними NLRI, неминучу convergence при постійній зміні
наміру, порожній RIB після shutdown чи виконання правила upstream-маршрутизатором.
Наявні 64 кандидати за раунд, call timeout, pacing і shutdown budget залишаються
межами роботи; жодна з них не є обіцянкою часу convergence або глобальним rate limit.

## Правило зупинки й перегляду

Runtime-зміна FlowSpec потребує відтвореного порушення чинного контракту в підтримуваному
профілі або конкретної потреби пілоту з критерієм прийняття. Для виправлення потрібні
регресія на фактичному worker, що падає на попередній поведінці, та відповідні
перевірки відмови/відновлення. CI й окреме рев'ю стосуються точного head.

Без такого входу не додаємо fairness, retry, метрики чи ще один стан worker.
Підтверджена критична вразливість або дефект залежності також дозволяють виправлення.
Якщо відтворення на worker небезпечне чи непридатне, PR має зафіксувати джерело,
уражений шлях, причину відсутності такої регресії та відповідну перевірку виправлення;
вимоги окремого рев'ю й CI залишаються. Нова потреба конкурентних writers або
невідповідність виміряним операційним порогам вимагає перегляду цього ADR, а не
мовчазного розширення гарантій. Історія R-PR сама не обґрунтовує наступний R-PR.

## gRPC як окремий кандидат

Тег GoBGP `v4.9.0` звірено з commit `01c5c4c27f9a1ac3b5927f433b5115f9b0eee791`
2026-10-05. Нижче закріплено джерела API; CI окремо перевіряє SHA256 release binaries.

У закріпленому [API GoBGP](https://github.com/osrg/gobgp/blob/01c5c4c27f9a1ac3b5927f433b5115f9b0eee791/proto/api/gobgp.proto#L303-L321)
AddPath повертає UUID, DeletePath може адресувати його;
[Path](https://github.com/osrg/gobgp/blob/01c5c4c27f9a1ac3b5927f433b5115f9b0eee791/proto/api/gobgp.proto#L670-L692) також має identifiers.
Проте AddPath не приймає очікуваної версії попереднього RIB. У
[server](https://github.com/osrg/gobgp/blob/01c5c4c27f9a1ac3b5927f433b5115f9b0eee791/pkg/server/server.go#L2533-L2645)
це окремі операції, не CAS між ListPath і AddPath. Точніше адресування не усуває
невідомого результату чи потреби readback; UUID сам не підтверджує ownership.
Не всі виправлення контролера були
спричинені CLI: актуальність наміру, health і бюджет потрібні з будь-яким backend.

Експеримент відкриваємо, якщо конкретному deployment потрібні точні identifiers
або виміряна ціна CLI порушує прийнятий поріг. До написання адаптера фіксуємо
baseline CLI, потрібну гарантію/поріг і межу витрат. На тому самому GoBGP перевіряємо
IPv4/IPv6, чужі й hidden-ID paths, конкурентний запис, втрату відповіді після
прийняття, пізній ефект після cancellation та restart Sokol і gobgpd.

Міграція виправдана лише демонстрацією потрібної сильнішої гарантії або виміряного
виграшу проти baseline без втрати чинних гарантій; враховуємо залежності й вартість
підтримки. Якщо результат негативний чи непевний, експеримент зупиняємо. Переїзд
на gRPC сам по собі не є qualification; production-перехід потребує нового рішення.

## Перевірка рішення

Чинний контракт реалізують `orchestrator/src/flowspec.rs`, ADR-0008 і сценарії
[INVARIANTS](../INVARIANTS.md); обов'язкові native x86/ARM CI й
Stargate shadow лишаються незмінними. Цей ADR не додає runtime чи нових повноважень.
Відповідальний оператор має записати NIC/driver, навантаження, SLO/RPO/RTO,
допустиму шкоду false positive та результати за [RUNBOOK](../RUNBOOK.md).
`main` захищено ruleset `protect-main` (обов'язкові CI-перевірки, без approve);
агентне рев'ю PR не є GitHub enforcement.
