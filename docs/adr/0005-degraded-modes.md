# ADR-0005. Захист не вимикається через збої допоміжних частин

**Статус:** реалізовано (PR #16, #28, #41). **Дата:** 2026-09-27.

## Контекст

Аудит, файл стану й меш — допоміжні частини. Якщо захист залежить від них, атакувальник, що
заповнив диск або розірвав меш, вимикає захист. Якщо ж збій мовчазний, оператор вірить у те,
чого немає.

## Рішення

- **Enforcement не зупиняється** через збій аудиту, файлу стану чи мешу. Вузол переходить у
  **DEGRADED** (`MODE=DEGRADED` у heartbeat, метрики нижче) і каже, чого саме бракує.
- **Аудит.**
  - Один процес-записувач на журнал (lock-файл `<db-path>.lock`).
  - «Записано» означає лише успішний `fsync` (кожні 100 мс).
  - Після збою writer отруєний, втрачені записи рахуються й позначаються записом `AUDIT_LOST`.
  - Метрики `sokol_audit_*`.
- **Стан.** Збій запису, зміна, що чекає на диск понад 5 с, або провал відновлення дають
  DEGRADED (ADR-0004).
- **Меш.** Кожен вузол і без мешу застосовує власні рішення та бани оператора. Меш лише
  поширює їх.
- **Невідоме не видається за успіх.** Відповідь оператору розрізняє `OK`, `OK …; WARNING: not
  yet durable`, `refused` і `ERR`. Рахуються лише ті блоки, що справді є в ядрі.

## Розглянуті варіанти

- **Fail-closed: без аудиту чи стану блоки не застосовуються.** Це перевернутий стимул:
  заповнений диск вимикає захист.
- **Працювати мовчки.** «Записано» могло бути неправдою.
- **Відхиляти ручні дії оператора без аудиту.** Можливе для окремих класів рішень, якщо цього
  вимагатиме регулятор.

## Наслідки

- DEGRADED — сигнал для оператора, а не стан, з якого вузол виходить сам.
  - Відновлення стану вимагає явного `ACCEPT_STATE_LOSS`.
  - Аудит і запис стану одужують самі, щойно диск знову приймає записи.

## Перевірка

- Аудит: `a_second_writer_is_refused_while_the_first_holds_the_log`,
  `a_failed_write_that_cannot_be_undone_poisons_the_writer`, `torn_tail_is_truncated_on_open`.
- Заповнений диск аудиту (tmpfs) перевірено окремим живим сценарієм, поза CI:
  enforcement триває, вузол у DEGRADED, потім `AUDIT_LOST`.
- Стан: smoke із завислим і пошкодженим файлом стану (ADR-0004).

## Коли переглянути

Якщо регулятор вимагатиме «без запису — без дії» для певних класів рішень.
